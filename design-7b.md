## 1. What 7b is, in the language's own terms

Braid already says, in four places, that a resource is a functor applied
to a scope: MANUAL §3's label table (carrier *a wire of type `R`*,
minted by *`with R`*); design-macros.md's "the manifest, stated once"
(functor `E ⊗ –`, fibre `C(E⊗Σ, E⊗Θ)` — Power–Robinson's state
construction); MANUAL §6's `with` table (*routed: `R ⊗ –`, wires
written out of the base*); and `examples/prob.braid`, which **writes
that functor out by hand** and declares it a model of the Doctrine.

In none of those places is it true of the checker. Today:

- `with R` mints **no label**. `def f with R = dup ; *` has the raw type
  `R Int ρ0 ⇒ R Int ρ0` with a **pure** manifest `[REPL: :t! f]`. The
  `=R>` you see is a *display fold* over the stack's leading resource
  wires (`showArrowA`'s second clause, `leadingRes`) `[code]`, and it
  fires with no scope at all: `scoreByHand`, written by hand with `_`
  and `...` and no `with` anywhere, prints `Int ρ8 =Log Counter> Int ρ8`
  `[REPL: :defs]`.
- A label named `Log` and a resource named `Log` are two different
  things that print the same way, and when both are present the fold
  prints the name **twice**: a written `data Weird = Fn⟨R Int =R> R Int⟩`
  gives `unWeird : Weird ⇒ Fn⟨Int =R R> Int⟩` `[REPL]`.
- The routing pass (`elabScope`/`routeStage`, ~60 lines) and the
  transport pass (`runTransport`, 61 lines) do the same job twice, in
  two vocabularies, and neither knows about the other.

**Stage 7b makes the four statements true.** Two changes and one
consequence.

**1. A resource is a model of the Doctrine.** With hom-objects over
stacks (7a) the carrier is direct — no pairing, no arity, no strength:

```braid
resource Log = Str
#   generates, besides `Log`/`unLog`:
#   data LogK(a..., b...) = Fn⟨Log a ⇒ Log b⟩
#   theory LogT(k(..., ...)) in Doctrine = compose : …, embed : …
#   model Log in LogT(LogK) = compose = …, embed = …
```

`embed` whiskers the resource wire past a pure stage — *exactly* what
`routeStage` writes today as the `_` padding — and `compose` is base
composition of representatives. `with Log` becomes transport into that
model; the routing pass becomes a special case of the transport pass.
Install is the entry; the handler (`collectLog`) is the exit.

**2. Labels carry their carrier in the grade set.** One label
mechanism: every label names a functor, and the functor's carrier is
looked up from the label's own declaration. A resource label's functor
is `E ⊗ –`; a carrier-less label's is the identity on homs. The order
`L ≤ L ∪ M` between fibres is whiskering by the extra carrier where
there is one and the identity where there is not. `IO` stops being an
exception in the *statement*: it is a label whose carrier is an abstract
linear `World`, and the four io prims are ordinary words at a resource
nobody can name.

**3. The consequence.** Everything `with` accepts is then a model or a
functor — `functor F = word` being a model of `Base` whose image is a
`Code ⇒ Code` word — so the fork inside `with` is a fork on the
*theory*, not on a keyword. That is what makes stage 8's six-keyword
surface honest.

## 2. The mathematics (one page)

**The construct** is design-macros.md's, unchanged: an arrow `Σ =L> Θ`
is a morphism of grade `L` in a closed Freyd category, graded by the
join-semilattice `(P(Labels), ∪, ∅)` with subeffecting, freely
generated by the vocabulary and presented concatenatively. 7b changes
only item 3 of that list — carriers — and changes it from *display* to
*inference*.

**Fibres.** For a grade `L` write `E_L = E₁ ⊗ … ⊗ E_k` for the tensor of
the carriers of the carriered labels in `L` (∅ for the carrier-less
ones). The fibre over `L` is

```text
K_L(Σ, Θ)  =  C(E_L ⊗ Σ, E_L ⊗ Θ)
```

— Power & Robinson's **state construction** (MSCS 1997), cited in
READING.md for exactly this. Each fibre is a category (identity
`id_{E⊗Σ}`, composition in `C`) and it is **representable**: the
hom-object is a genuine object of `C`, namely `Fn⟨E ρ ⇒ E σ⟩`, so fibre
composition *is* base composition of representatives. That is the plan's
settled "`;` is always base composition", and 7a is what makes the
representative writable, because `ρ` and `σ` are stacks.

**The order.** For `L ⊆ M` the inclusion `K_L ⊆ K_M` is whiskering by
the extra carriers, `f ↦ id_{E_{M∖L}} ⊗ f`; for carrier-less labels it
is the identity on homs and the fibre is a marked copy of the base. That
is Katsumata's ordered-monoid grading (POPL 2014) with Gifford–Lucassen
set inclusion as the order, and Orchard & Petricek's Fig. 2(a) `(sub)`
rule as the same filtration `K≤L ⊆ K≤M`. Composition **joins**
(Talpin–Jouvelot: a constraint set `part ⊆ composite`, principal type =
least solution), which shipped at 5a⁹⁄₁₀ and 7b does not touch.

**The total category** is the Grothendieck construction `∫_L K_L` over
the semilattice as a poset-shaped indexing category: an object is a
stack, a morphism is a pair `(L, f)` with `f ∈ K_L(Σ, Θ)`, and
composition joins the grades and whiskers both sides into the join's
fibre first. **Whiskering is what the elaborator writes.**
`routeStage`'s `_`-padding is the whiskering map for one carrier;
`swapStage` is the symmetry that reorders a carrier segment so a
narrower operation lands in the right fibre.

**Handlers** are **grade-decrementing model morphisms**: `K_{L∪{E}} →
K_L`, given by the unit (`seed`) and counit (`unwrap`) of the `E ⊗ –`
adjunction. `examples/resources.braid` writes one as an ordinary word,
`def collected in Collector = (f -> [f (seed) ... ; ev ; unwrap ...])`
— Plotkin–Pretnar's *handlers are models* with no construct at all.
`Collector(e, a)` is the algebraic theory, the model is the algebra,
`collected` is the induced map out of the free one.

**Where this sits.** Power & Thielecke's κ-categories "correspond to an
idealisation of stack-based intermediate languages"; Braid is one, and
the resource fibre is the state construction on it. Tate's productors
and Gordon's flow-sensitive effects are the reference for what Braid is
*not* doing — order in the grade (§8).
Gaboardi–Katsumata–Orchard–Breuvart is where the coeffect half lands.

## 3. The mechanism, piece by piece

### 3.1 What `resource R = Ty` generates

Today `resource` is `data` under another keyword: one flag on
`DataDecl` (`parseTypeLine`, `kw == "resource"`), the roll and unroll,
and no `foldR` `[code]`. 7b adds three generated declarations beside
those:

| generated | shape |
|---|---|
| the carrier | `data R@k(a..., b...) = Fn⟨R a ⇒ R b⟩` |
| the theory | `theory R@t(k(..., ...)) in Doctrine = compose : k(a,b) k(b,c) ⇒ k(a,c), embed : Fn⟨a ⇒ b⟩ ⇒ k(a,b)` |
| the model | `model R in R@t(R@k) = compose = R@then, embed = R@arr` |

with the two images being, verbatim, the shapes `prob.braid` writes by
hand for `Samp`:

```braid
def R@arr  = (f -> [_ f ... ; _ ev] ; R@k)
def R@then = (c e -> [c ... ; unR@k ... ; ev ; e ... ; unR@k ... ; ev] ; R@k)
```

**The theory declares only `compose` and `embed`, deliberately.** MANUAL
§8's two-level table says that is enough for `with M` to transport any
stage, and it also means **no inherited law runs**: `instanceDefs`'
`inherited` filter keeps a doctrine law only when every doctrine slot it
names is one this theory declares `[code]`, and all five Doctrine laws
name `observe` and `sample` `[code: the prelude's `theory Doctrine`
block]`. That is forced, not lazy. `observe : k(Int,Int) ⇒ Int` would
have to run a resource program, which needs a **seed**, and the settled
position is *seeds at the install site only, no declared defaults* — a
generated `observe` would be `mempty`-conjuring by another name. So the
resource model is honestly unaudited, which the Doctrine's own comment
blesses for a category that declares no way out; the category laws hold
by construction (`embed` is padding, `compose` is `;`) and `sameCode`
could prove them later as a `model … in Base` obligation.

Touch points: `parseTypeLine` (the keyword), `checkModuleRaw`'s
declaration hoist (where the three generated lines are appended, the
same way `table` appends its generated `data` line), `transportOf` (it
already reads the shape and will now see a generated theory `in
Doctrine`), `ElabCtx.ecTrans`, `ModuleBase.mbTrans`.

### 3.2 `with R` becomes transport — in fused form

`elabHeaders`' `go` applies a header's names in a fixed order —
templates expand, models rename, **resources route**, a carrier model
transports, functors rewrite `[code]`. 7b merges the third step into the
fourth. But it must merge them **fused**, not literally: a resource
model's fibre is representable, so `embed [s] ; compose` has a normal
form that is `_^k s ... ; ` — the very thing `routeStage` emits. Running
the unfused `runTransport` for resources would build and immediately
destroy an `R@k` wrapper at every stage, change every reflected program,
and break `metered.braid` (§7).

So the rule is: **`runTransport` gains a fused path, taken exactly when
the model is representable** (its carrier's body is an `Fn⟨E ρ ⇒ E σ⟩`
whose `E` is the model's own resource). On that path `embed [s]` emits
`_ s ...` and `compose` emits nothing, which is `routeStage`'s pure
branch character for character `[code: it emits `pad k ++ atoms ++
tailPass`]`. Everything `elabScope` does that transport does not — the
claim assertion, the one-resource-op stage, the whole-scope word, the
two refusals — stays in the fused path, and is what `routeStage`
already is. This is a **re-statement, not a deletion**: the routing code
survives as the fused evaluator of the resource model, and what goes is
the idea that routing is a separate kind of scope.

### 3.3 The label, minted and folded

Two halves, and they must be kept apart because only one of them is safe.

*The mint.* `with R` joins `mine` in `elabHeaders`' `marks`, so `R`
lands in the manifest `[code: `mine = [ n | n <- map fst is ++ map fst
bs, … ]` — resources `rs` are absent today]`. **But the receipt must
not be a new stage.** `marks` prepends `with@F` atoms, and a resource
scope already emits a stage of its own — the claim assertion `unR ; R`
(`elabScope`'s `assert`) `[code]`. Give *that* stage the label instead
of prepending a second one: `assert` becomes `with@R ; unR ; R` inside
one stage, or `receiptScheme R` is composed into the assert's line. Then
the elaborated spine has the same number of stages it has today, which
`metered.braid` depends on to the character (§7).

*The fold.* `showArrowA` keeps reading the carrier off the **stack**,
not off the set. A carriered label's display position is its carrier's
position, because the carrier segment is an ordered object and the grade
is not. Concretely `arrowBetween` becomes

```haskell
arrowBetween e ns = " =" ++ unwords (S.toList (eLabels e S.\\ S.fromList ns) ++ ns) ++ "> "
```

— subtract the folded carriered labels from the sorted set, then append
them in carrier order. That is byte-identical to today (today the
resources are not in the set at all, so the subtraction is a no-op) and
it fixes the `=R R>` double print `[REPL: `unWeird`]`.

Touch points: `Disp` (it already carries `dispResources` and
`dispModes`; the two become one carrier table), `arrowBetween`,
`showArrowA`'s two fold clauses (they merge), `receiptScheme`,
`elabHeaders`' `marks`, `elabScope`'s `assert`.

### 3.4 What inference gains

One thing, and it is the user-visible payoff: **a resource mismatch
becomes a nominal row error naming the label.** Today, calling a
`Log`-threading word without the wire is `Cannot unify stacks: Log Int
vs Int` — a shape error about a wire the user never wrote. With the
label in the manifest, the composite carries `Log` and a *written* pure
expectation refuses it with `unifyEff`'s existing message and repair
hint `[code: `hint`/`repair`]`. That is the best error in the system —
*you forgot to install* — and the reason the label has to be minted at
all. The solver itself changes **nothing**: `EffRow` stays
`Set String`, `unifyEff` keeps its bridge case, and
`CSubEff`/`fixSubs`/`keepSubs`/`subsumes` are untouched (§4a).

## 4. The open questions

### (a) Ordered carrier segment + provenance set, or one set with carriers attached?

*Context.* Daniel observed (2026-09-17) that grades-as-nested-scopes
with `A;A = A` and absorption of comparable sequences is a well-nesting
discipline — regions, scoped effects — and that for carriered labels
**the resource segment of the stack already is that sequence**:
composition is unification of segments, exits are handlers, and it
collapses to a set up to `swap`. He did not finalize it; the lead
proposed it.

**Reading A — the manifest is `⟨E₁ … E_k | ρ⟩ , L`:** an ordered,
possibly-open sequence of carriers plus a set of carrier-less labels.
*Buys:* the display order is in the type, so `=Log Counter>` survives by
construction; the whiskering functor is segment inclusion with an
explicit permutation, which is what `swapStage` is; regions and scoped
effects become statable. *Costs:* two sorts in the manifest, so
`unifyEff` becomes two algorithms and the second one is **stack
unification again** — rigid, front-anchored, no suffix matching
(design-effects.md's own survey, still true `[code: `unifyStack`]`).
Sequence subsumption with absorption of comparable subsequences is *not*
a semilattice: subsequence embedding has several minimal solutions, so
the Horn-clause argument that gives `solve` its least fixpoint does not
carry over and principality must be re-proved. `subsumes` grows a second
comparison. The display fold gets simpler; nothing else does.

**Reading B — one set, each label's carrier looked up from its
declaration:** the manifest stays `Set String`; `Log`'s carrier is
`Log ⊗ –` because `resource Log` says so, `Notes`' is `Logged(a,b)`
because `transportOf` says so, `Metered`'s is nothing because `functor`
says so. *Buys:* **zero solver change** — `EffRow`, `unifyEff`,
`CSubEff`, `fixSubs`, `keepSubs`, `subsumes`, `subsumesShape`,
`generalizeWith` all untouched, principality the one already proved.
It is also literally what "the manifest, stated once" wrote down: one
table, four rows, every difference in the carrier column. *Costs:* the
order of the carrier wires is not in the manifest, so display must read
it from somewhere else.

**Recommendation: B, with the ordering located rather than duplicated.**
Daniel's observation is right, and its conclusion is that the ordered
sequence should *not* go in the manifest — because the stack already
holds it. The grade says *which* fibre; the object says *how the
carriers are stacked*. Display reads the order off the carrier,
available precisely because the fibre is representable, which is already
what `showArrowA` does. A costs a second unification theory and a
principality re-proof for a fact the stack already records; B costs one
display rule (§3.3) that is byte-identical to today's. Keep reading A in
the record as the correct description of the *objects* — the carrier
segment is the well-nesting discipline, `swapStage` is its symmetry —
and as the door to regions if scoped effects ever need to be in the
type.

### (b) `IO` with a linear `World` carrier

**What changes for users: nothing visible.** `print : a0 =IO> •` stays
`[REPL]`, because the display fold hides a carrier the same way it hides
`Log`. No example, no test, no doc line changes.

**What changes in the checker.** The four prims stop being "marked" and
become ordinary words at a carrier: `print : World a0 ⇒ World` with the
label `IO` in the manifest, the same shape `note : Log Str ⇒ Log` has.
Two sub-readings:

- *b1 — `World` is a real wire.* Every def containing an io prim gets a
  World wire routed through it, and `main` installs one. Honest, and it
  is design-effects stage 5's "explicit" zoom level. It is also a
  language-wide break: a bare `print` in the REPL would need a world on
  the stack. Out.
- *b2 — `World` is a singleton carrier the elaborator never writes.*
  The fibre is `C(World⊗Σ, World⊗Θ)`, but there is exactly one `World`
  and it is ambient, so every representative is determined and the
  whiskering map is the identity. This is Clean's `*World` and GHC's
  `State# RealWorld` with the wire erased because it is a singleton.

**Recommendation: b2.** 7b delivers the *statement* — the label table's
`IO` row stops being an exception, and the prelude declares `IO` as a
carriered label whose carrier is abstract — while the mechanism stays
what it is. The "pre-applied" exception goes away as a special case in
the prose; it does not go away as an implementation shortcut, and the
note should say so plainly rather than claim more.

**Routed like a resource?** No: by b2 the routing is the identity.
**Discharged?** No, and the enforcement is structural rather than a
check — `World` is not declared by `resource`, so the `data` machinery
never generates `World`/`unWorld`, and a handler is exactly
`seed ; … ; unwrap`. There is no constructor to write one with.
Linearity needs no mark until the explicit level exists; when it does,
design-effects.md already has the design (an internal must-copy mark on
`dup`/`drop`/`forget`/ignored binder params, one unification failure, no
syntax).

**Does `=IO>` remain a label of its own?** It remains a label *like any
other in the table*, but not a `resource` declaration: a
prelude-declared carriered label with an **abstract** carrier — no roll,
no unroll, no seed, no handler. One mechanism, with the exception
recorded as a property of the carrier rather than a branch in the
checker.

### (c) `resource Log = Str` — sugar, or make users write the model?

**Recommendation: keep the spelling; generate the model; do not make
users write it.** Spelling is stage 8's business. What it generates is
§3.1's three declarations plus the label's carrier entry, on two
conditions: the generated model is **visible** (`:doc Log` shows the
carrier, the theory and the two images, exactly as `table` shows the
`data` line it wrote — sugar you cannot read is a feature, not a
desugaring), and the generated names sit in the compiler's namespace
(`R@k`, `R@t`, `R@arr`, `R@then`), refused in source by the existing
`@` rule `[code: `elabHeaders`'s `go (Prim n)`]`.

The alternative — writing the model by hand — is already available and
already exercised: `prob.braid`'s `Sampler` is the hand-written case,
and it is hand-written for a reason (`Samp` is used as a **value**,
passed to `under`, folded over 200 draws). Both spellings must keep
working, which is another argument for the generated one being an
ordinary model rather than a compiler secret.

### (d) The commuting-functors check (tabled; where it would attach)

Not designed here. The attachment point is `elabHeaders`' `go (With ap
ns b)`, after the four kind-lists are partitioned and before `marks` is
prepended. The three same-kind cases are not alike: **two carrier
models** are already refused by name *("a clause may name at most one
category")* `[code]`; **two resources** need no check — `elabScope`
fixes the order from the header and disjoint wires commute by geometry
(design-effects' ladder step 3), with a refusal already firing when a
word threads them in the other order `[test: "threads Log Counter, but
this scope is over Counter Log"]`; **two functors** are folded left to
right, and functor composition of `Code ⇒ Code` words is `;` `[code]`,
so the check would be `sameCodeC (F ; G) (G ; F)` **at this scope's own
body**, refusal or warning depending on whether the receipt `F G` is
meant to name an ordered composite. That last decision is what is
tabled.

### (e) A `Show` for stacks

7a's regression: `examples/lifting.braid` logs a `Box` and a box renders
as the one-alternative sum it is, so the log line reads `alt1(100)
alt1(212)` where it used to read `100 212`.

*Where it lives:* a **prim**, beside `toStr`, not a derived word. A
derived one is unwritable — rendering a stack needs the width and the
per-wire renderer, and `dup` copies a wire while `pack` wants a
homogeneous bundle. The evaluator has the values and already renders a
stack: `:s` does it.

*Its type:* `showStack : ρ0 ⇒ Str`. Consuming, open-tailed (so the
existing final-atom rule applies and nothing new is needed), wires
deepest-first and space-separated by the REPL's own stack printer. It is
a **renderer, not a class** — it does not compose into user-defined
rendering, and `primDocs` should say so.

`lifting.braid`'s logger then reads `(unBox ; showStack)` inside a group
and the printed line goes back to `100 212`: an output change, a
deliberate one undoing a regression, which is why this ships as its own
commit, first, where the diff is one line.

### (f) What 7b delivers vs defers

**Delivers.**

- A resource is a model of the Doctrine (§3.1), and `with R` is
  transport in fused form (§3.2).
- One label mechanism: `with R` mints, the display fold is driven by
  label-plus-carrier, and the `=R R>` double print is fixed (§3.3).
- `IO`'s carrier declared abstract and linear, b2 (§4b).
- A resource mismatch is a nominal row error naming the label (§3.4) —
  *you forgot to install*.
- `;` is always base composition — already true, now a theorem about
  representable fibres rather than an accident.
- `showStack` (§4e).
- The never-an-error list re-verified: pure∘effectful (absorption),
  label∘label (union), label order (sets), unused labels.

**Already delivered — the plan's stage-7 text is stale here.**
*Traversals get ε.* The plan lists `mapE : Fn⟨a =ε> b⟩ List(a) =ε>
List(b)` as a stage-7 item with "today's spelling is the payroll fold".
It shipped with composition-joins: `[toStr >> print >> 1] id ... >> map
: List(a0) =IO> List(Int)` `[REPL]`. `map`'s displayed type is pure
because constraints are hidden, not because it is monomorphic. Nothing
to do.

**Defers.** *Install/reify as a pair packing and unpacking the
existential* (`Circuit(a,b)` value ⇄ `a =Motor> b` ticking resource) —
it needs a crossing between a non-representable carrier and a
representable one, and 7b's whole point is that the representable case
is the one that fuses; own stage. *The coeffect half* ("every stage is
metered", intersection) — out by the plan's own text, with the nominal
wrapper staying the documented idiom, as `metered.braid`'s own comment
says. *The explicit and split zoom levels* (a nameable `World`,
per-resource wires) — position only, as design-effects stage 5 has it.
*Resources leaving the stack type* — see §7 and the appendix.

### (h) How the transport pass absorbs routing, with the carrier deepest

**The model's `embed` puts `E` below:**

```text
embed : Fn⟨ρ ⇒ σ⟩ ⇒ Fn⟨E ρ ⇒ E σ⟩
```

and a stage with passengers above is `embed [f ...]` — the passengers
ride **inside** the quotation, whiskered in the base by 7a's `...`, and
the carrier is added **outside** it by `embed`. Two different
directions, no conflict: 7a's finding was that `embed` has nothing to
commute with *because the whiskering already happened in the base*, and
that is still true when `embed` itself adds a wire underneath.

Checked three ways, and they agree.

*Against `prob.braid`, which wrote it by hand `[code: examples/prob.braid]`:*

```braid
data Samp(a..., b...) = Fn⟨Rng a =Recursive> Rng b⟩
def sEmbed  = (f -> [_ f ... ; _ ev] ; Samp)
def sCompose = (c e -> [c ... ; runS ; e ... ; runS] ; Samp)
```

`Rng` is leftmost and leftmost is deepest; `_` counts from the deepest,
so `_ f ...` is "step over the carrier, run `f` on everything above".
The task's claim — that `Sampler` is a resource-shaped Doctrine model
already — is **verified**: `sEmbed` is `embed` at `E = Rng`, one `_`
deep, and `sCompose` is composition of representatives.

*Against `routeStage` today:* the pure branch emits `pad k ++ atoms ++
tailPass`, i.e. `_^k <atoms> ...` `[code]`. At `k = 1` that is `_ f ...`
— `sEmbed`'s body with the `Samp` wrapper and the `ev` removed, which is
exactly the fusion of a representable `embed`; and `;` is `sCompose`
fused.

**The one place they differ is the narrow operation.** `note : Str
=Log> •` is a carrier at a fixed width in the `Log` fibre only, but the
scope may be over `Log Counter`. It must be whiskered into the larger
fibre *and* the carrier segment permuted so `Log` is adjacent. That is
`routeStage`'s `swapStage` ladder `[code]`, and in the model language it
is: the fibre map `K_{Log} → K_{Log,Counter}` composed with the symmetry
of the carrier segment. The permutation is exactly what makes the
general subset case hard (design-effects: "a subset at once would need a
solved permutation rather than a fixed `_`-prefix"), and 7b does **not**
relax it. The limit is unchanged; what changes is that it now has a
name.

### (i) Inferred routing

*Approved by Daniel 2026-09-17, after the rest of this note was written.*

A `with E` header on a def that merely *calls* a resource word says
nothing the callee's own type did not already say. The four io prims
originate `IO` at the leaf and the label propagates by row unification;
a resource word should originate its label the same way.

**RULE.** A def is **routed** for a resource `E` when the scheme (from
the prefix scope) of any atom in its body carries `E` as its deepest
wire on **both** sides. Routing then proceeds exactly as if `with E`
were written: the wire is padded under every other stage, the def's
arrow becomes `E Σ ⇒ E Σ′` (displayed `Σ =E> Σ′`), and callers are
routed the same way, transitively, until the wire meets an **install
site** (a written seed) or a **handler** (a discharge). No header
needed. Resource words thus originate their label at the leaf, exactly
as the four io prims do, and the label propagates by row unification as
every label does.

**EXCEPTION (syntactic, two atoms).** A def whose body names the
carrier's constructor or un-constructor (`Log` / `unLog`) is handling
the wire itself — an install site or a handler — and is **never**
auto-routed (padding would add a second wire beside the one it holds).
This keeps the handler idiom (`collected`, install at the site) working
unchanged.

**`with E` stays.** For a resource it remains legal, is exactly
equivalent to what inference does (routing is idempotent), and is the
explicit **override** for the one rare edge: a def that receives the
carrier as a **value** (through a binder, without naming the
constructors) and also calls a resource word — inference would route it
and it would fail loudly with two `E` wires; the header says what is
meant. Never silent: the carrier is nominal, a `Str` is never a `Log`,
and a missing install stays *you forgot to install*.

**Invariant five** gains one sentence: routing may read the schemes of
callees in the prefix scope (fixed before the current def is touched —
as good as written, the same license `typeOfCode` and the 5c½ strength
routing use); it never reads the manifest of the def being elaborated.

**A `:t!` diagnostic line.** When a def was routed by inference, `:t!`
prints why (`routed for Log: calls \`log\``).

**Tests.** A header-less def calling a resource word types `=E>` and
runs; a chain of three header-less defs to an install site; the handler
idiom unchanged; the pass-through-as-value edge fails naming two
carriers and the header fixes it; `with E` on an already-routed def is
a no-op (byte-identical elaborated code).

## 7. Risks, and the byte-identical audit

The bar is that every example's printed output stays byte-identical
except `lifting.braid`'s one log line (commit 1, deliberate). Here is
every place that is at risk, each with the evidence.

**R1 — the receipt stage, and `metered.braid`'s burn count. Sharpest.**
`elabHeaders` prepends a `with@F` **stage** per mint `[code]`.
`metered.braid` prints its own elaborated wiring and counts stages by
burning fuel `[REPL, the shipped output]`:

```text
(unFuel >> Fuel) pass >> burn pass >> _ dup pass >> burn pass >> _ * pass
  >> burn pass >> _ dup pass >> burn pass >> _ + pass >> burn pass
  >> _ _ 1 pass >> burn pass >> _ + pass >> burn pass
```

Seven `burn`s, `10 - 7 = 3` fuel left. A prepended `with@Fuel` stage
makes it eight, prints an extra token, and leaves 2. **Both printed
lines change.** Mitigation (§3.3): put the label on the claim assertion,
which is already one stage and already burns a unit. Test: diff the
wiring line.

**R2 — the display order of resources against labels.** `arrowBetween`
today emits *labels sorted, then resources in carrier order* `[code]`.
Merging resources into the sorted set changes four shipped displays, all
verified:

| today `[REPL]` | if merged into one sorted set |
|---|---|
| `score : Int ρ0 =Log Counter> Int ρ0` | `=Counter Log>` |
| `poly : Int ρ0 =Metered Fuel> Int ρ0` | `=Fuel Metered>` |
| `step : Int ρ0 =Hourly Books> ρ0` | `=Books Hourly>` |
| `p : a0 ρ0 =IO Alpha> a0 ρ0` | `=Alpha IO>` |

and it is pinned by tests, not only by examples: `test/Tests.hs` carries
`"• =IO Log> •"` and `"Int ρ0 =Log Counter> Int ρ0"` `[code]`.
Mitigation: §3.3's subtraction. This is the single strongest argument
for reading B in §4(a).

**R3 — the display fold firing without a scope.** `scoreByHand` has the
resource prefix and no `with`, and folds today `[REPL: :defs]`. If the
fold is switched to being label-driven it stops folding and the type
grows two wires. Mitigation: keep the fold prefix-driven; the label is a
*consistency* requirement where present, never a precondition.

**R4 — `interpose`'s `subsumesShape` with resources.** `subsumesShape`
compares the **wires** and leaves the manifest free `[code]`, which is
why `burn ...` fits after every routed stage and does **not** fit into
an unrouted one. `metered.braid`'s last two lines depend on exactly
that: `([metered] [dup ; *] ; lift2) 5 ; ev ; print` prints `25` because
the metered code needs a Fuel wire the program never had `[REPL]`. If
the resource wire ever left the stack type, `subsumesShape` would admit
`burn` everywhere and the refusal would move into `lift2`'s witness
unification instead. The printed `25` would probably survive — but by a
different mechanism, and "probably" is not the bar. **Mitigation: the
carrier stays a wire.** This is the reason.

**R5 — `lift2`.** `lift2 : Fn⟨Code ⇒ Code⟩ Fn⟨ρ0 ⇒ ρ1⟩ ⇒ Fn⟨ρ0 ⇒ ρ1⟩`
`[REPL]`: the two `Fn` rows are written, so they are compared exactly
(the "written meets written" half of the subeffecting rule). A newly
minted `Fuel` label inside the rewritten quote would make the result's
row `{Fuel}` and the witness would refuse it — which is the behaviour
the example wants, but it must be checked that it refuses for the right
reason and still prints `25` twice with `7` between them.

**R6 — the `Recursive` interaction.** `prob.braid`'s carrier is
`Fn⟨Rng a =Recursive> Rng b⟩` and its Doctrine slots are all
`=Recursive>`. A generated resource model's slots are **pure**. If a
generated carrier ever meets a `Recursive` body, the written-meets-
written rule bites. Nothing in the examples does this today; a test
should pin it before commit 4.

**R7 — new laws running at module start.** None, by §3.1: the generated
theory declares only `compose` and `embed`, and every Doctrine law names
`observe` or `sample`, so `instanceDefs`' `inherited` filter keeps none
`[code]`. Verify by diffing module-start output for every example.

**R8 — `:defs` and `:doc` surface area.** Commit 3 adds four generated
names per resource. They must not appear in `:defs` (they are the
compiler's spelling) and `:doc R` must show them deliberately. Seven
resources across the examples (`Log`, `Counter`, `Fuel`, `Books`,
`Game`, `Rng`, `Gradient`) × four names is twenty-eight new entries if
this is got wrong.

**R9 — reflected code.** `traced.braid` prints reflected code including
`with@Ticked` `[design-macros.md, "the receipt is `with@F`"]`. Any
change to what a resource scope elaborates to is visible there and in
`metered.braid`. Commit 4's test is a diff, not an assertion.

## 8. What is explicitly out

- **Quantitative grades** (cost, privacy). Non-idempotent sequential
  composition, a different unification theory, its own arc.
- **Manifest-triggered rewriting.** Circular while the language is
  annotation-free; reopens only if written ascriptions land.
- **The coeffect half.** "Every stage is metered" intersects where
  effects union; it is a graded comonad and it is not this stage. The
  nominal wrapper stays the documented idiom.
- **Non-representable resources.** If there is no nameable `E`, it is
  not a resource — it is a value plus a functor, which is what
  `Circuits` is.
- **Nondeterminism / `List` as a label.** No carrier `E` exists: it
  changes the output shape, not the threaded state. It stays data on the
  wire.
- **Declared seeds and defaults.** Install-site only. A declared default
  is `mempty`-conjuring and it papers over the best error in the system.
- **Order in the grade** (typestate, traces). Tate's productors and
  Gordon's flow-sensitive effects are the reference for what a future
  *product component* would look like; provenance never becomes
  non-idempotent.
- **Relaxing the routing limits** — one resource operation per stage,
  alone; no operation over a strict subset of the scope. Both still want
  a solved permutation. 7b names them; it does not lift them.

## Appendix: what contradicts the plan's settled text

Two items, both recorded so the amendment does not quietly overwrite
them.

1. **"Resources move out of the stack type into the row"** (plan, stage
   7 follow-on, first bullet). This cannot be squared with the same
   section's next bullet, "every fibre is representable … fibre
   composition IS base composition of representatives", nor with 7a's
   `Fn⟨E ρ ⇒ E σ⟩` carrier. A representable fibre's hom-object *is* an
   object of the base, so the carrier is a wire; what moves into the row
   is the **label**, which then names the carrier. §7's R4 gives the
   concrete cost of moving the wire (`interpose`'s shape check stops
   discriminating and `metered.braid`'s last two lines change
   mechanism). Recommendation: amend the bullet to *the label moves into
   the row and names the carrier; the carrier stays a wire, because the
   fibre is representable*.

2. **"Traversals get ε: `mapE : Fn⟨a =ε> b⟩ List(a) =ε> List(b)`;
   today's spelling is the payroll fold"** (plan, stage 7 follow-on).
   Already shipped. `[toStr >> print >> 1] id ... >> map : List(a0)
   =IO> List(Int)` `[REPL]` — `map`'s displayed type is pure only
   because `showSchemeA` hides the `⊆` constraints it carries. The
   bullet should be struck, not scheduled.

One smaller correction, to the docs rather than the plan:

3. **MANUAL §3's label table** lists `R (any resource)` as *minted by
   `with R`*. It is not minted at all today — the `=R>` is a display
   fold over the stack, and it fires with no `with` in sight
   (`scoreByHand`) `[REPL]`. The table describes the language 7b is
   for. It should stay as written and become true at commit 5, and the
   amendment should say that is what happened.
